# Release Manifest: Anticharon v0.6.1 Beta

**Sprint:** Multi-Wave Ecosystem Ergonomics & MCP Discoverability — Patch Release  
**Release Tag:** `v0.6.1-beta`  
**Date:** 2026-09-26  

---

## 1. Executive Summary

Anticharon `v0.6.1 Beta` refines the experimental host self-update subsystem following live host testing on a dedicated Hermes VM.

Key updates:
1. **Drop `phoenix_inverted` sequence:** Host validation confirmed that attempting to terminate the server before launching a background installer is prone to orphaned states. `phoenix_inverted` has been removed. The remaining 4 sequences (`install_only`, `restart_host`, `phoenix`, `reload_request`) ensure the new binary is safely compiled and installed before any termination or reload signals are dispatched.
2. **Version Bump to Enable Live Multi-Version Verification:** `v0.6.1-beta` is published as the latest release, allowing agent hosts on `v0.6.0-beta` to immediately detect `0.6.1` via `check_updates` / `anticharon check-updates` and verify the live update workflows.

---

## 2. Multi-Version Testing on Hermes Host VM

To test and verify the update workflow between release tags, run:

```bash
# Baseline installation (v0.6.0-beta):
uv tool install --force git+https://github.com/parisneto/anticharon.git@v0.6.0-beta

# Verify installed baseline:
anticharon -v
# Output: anticharon 0.6.0

# Check for updates (will detect v0.6.1-beta available):
anticharon check-updates

# Perform the upgrade to v0.6.1-beta:
anticharon update --type install_only

# Or force-install v0.6.1-beta directly:
uv tool install --force git+https://github.com/parisneto/anticharon.git@v0.6.1-beta

# Verify upgraded version:
anticharon -v
# Output: anticharon 0.6.1
```

---

## 3. Supported Update Sequences

With `phoenix_inverted` removed, the supported update sequences are:

| Option / Alias | Sequence Name | Behavior |
| :--- | :--- | :--- |
| `1` | `install_only` | Runs `uv tool install --force git+https://github.com/parisneto/anticharon.git` (or pip fallback) in-place without host restarts. |
| `2` | `restart_host` | Reinstalls binaries, then runs `hermes gateway restart` to restart the host. |
| `3` | `phoenix` | Reinstalls binaries, then terminates the MCP server process so the host automatically respawns it. |
| `4` | `reload_request` | Reinstalls binaries and advises the user to send `/reload-mcp` in Hermes chat. |
